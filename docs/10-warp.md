# 10. Cloudflare WARP как выход сервера

## Что это и чего это не делает

Свой «сервер WARP» поднять нельзя: WARP — это сеть Cloudflare. Можно другое — пустить трафик
**с нашего сервера дальше через WARP**:

```
Телефон ──VLESS/REALITY──▶ ваш VPS ──WireGuard──▶ Cloudflare WARP ──▶ сайт
                                   └─ остальное ─────────────────────▶ сайт (напрямую)
```

* Сайт видит **адрес Cloudflare**, а не адрес VPS. Это помогает, когда сервис не пускает адреса
  хостингов: капчи и «необычная активность» у Google, «регион не поддерживается» у ИИ-сервисов,
  ограничения стриминга, сайты, заблокировавшие подсеть вашего хостера.
* Адрес VPS не светится на этих сайтах.

**Чего WARP не делает:** не помогает, если провайдер режет соединение **между вами и VPS**
(обрыв рукопожатия, блокировка IP) — WARP стоит за сервером, а не перед ним. Для этого —
[07](07-cdn.md), [08](08-vless-encryption.md), [09](09-handshake-masking.md).

## Как устроено

* Бесплатный аккаунт WARP регистрирует утилита [wgcf](https://github.com/ViRb3/wgcf) (загружается
  с GitHub, проверяется по контрольной сумме релиза, запускается от `nobody`). Данные аккаунта —
  `/etc/xray/warp.json` (0600). Регистрация означает согласие с условиями Cloudflare.
* В Xray — исходящее подключение `wireguard` (тег `warp`) со встроенным стеком TCP/IP: Xray
  по-прежнему работает без прав администратора. DNS для сайтов через WARP — 1.1.1.1 внутри туннеля.
* **Автоматический запасной путь:** Xray раз в минуту проверяет WARP. Если он не отвечает, трафик,
  который должен был идти через WARP, идёт напрямую — VPN не ломается.
* Запреты сервера (частные сети, адреса самого сервера, SMTP, BitTorrent) действуют и для WARP.

## Включение

```bash
cd /opt/vpn-https-debian && git pull
cp warp-domains.example.txt warp-domains.txt && nano warp-domains.txt   # для WARP_ROUTE="domains"
nano config.env                       # WARP_ENABLE="yes", WARP_ROUTE="domains" или "all"
sudo ./scripts/03-install-vpn.sh      # зарегистрирует аккаунт и применит конфиг
sudo ./scripts/warp.sh test           # должно быть: warp=on, ip=... (адрес Cloudflare)
```

| `WARP_ROUTE` | Что идёт через WARP |
|---|---|
| `domains` (по умолчанию) | только сайты из `warp-domains.txt` — остальное напрямую, быстрее |
| `all` | весь трафик клиентов (кроме запрещённого) |

Список сайтов — по одному в строке: `example.com` (с поддоменами), `full:www.example.com`,
`geosite:netflix`, сети `203.0.113.0/24`, `geoip:XX`. После правки — `sudo ./scripts/03-install-vpn.sh`.

## Проверка и обслуживание

```bash
sudo ./scripts/warp.sh test           # временный Xray только через WARP -> cloudflare.com/cdn-cgi/trace
sudo ./scripts/healthcheck.sh         # раздел «Cloudflare WARP»
sudo ./scripts/warp.sh --force        # новый аккаунт WARP (другой адрес выхода), затем 03-install-vpn.sh
```

С телефона: при подключённом VPN откройте сайт из списка, например `https://www.cloudflare.com/cdn-cgi/trace`
(добавьте `cloudflare.com` в список для проверки) — строка `warp=on`.

| Симптом | Причина / решение |
|---|---|
| `warp.sh test`: нет ответа, в журнале `handshake` | UDP к Cloudflare (порт 2408) не проходит от хостера, или аккаунт отклонён: `warp.sh --force`; если не помогло — задайте `WARP_RESERVED` (client_id аккаунта, три числа) |
| `03-install-vpn.sh`: ошибка `geosite`/`geoip` | в `warp-domains.txt` тег, которого нет в базе Xray — уберите его |
| Сайт из списка всё равно видит адрес VPS | WARP недоступен и сработал запасной путь — `warp.sh test`; или сайт открыт по адресу, не попадающему в список (добавьте домен/сеть) |
| Через WARP медленно | бесплатный WARP не рассчитан на 40 Гбит/с; используйте `domains`, а не `all` |

## Ограничения — честно

* Бесплатный WARP — сервис Cloudflare без гарантий: скорость ниже, чем у прямого выхода, у
  Cloudflare есть лимиты регистраций, и условия использования могут измениться.
* Часть сайтов не пускает и адреса WARP (они тоже известны) — тогда WARP не поможет.
* Неофициальное API Cloudflare, через которое получается `reserved`, может ответить отказом — WARP
  обычно работает и без него.
