# 08. VLESS Encryption без TLS (эксперимент)

> Сравнение с другими способами обойти обрыв рукопожатия (фрагментация, маска) — в
> [09](09-handshake-masking.md).

## Зачем

В части сетей провайдер обрывает соединение с сервером **на TLS-рукопожатии**: TCP проходит, а
после ClientHello или ServerHello соединение рвётся — независимо от SNI и маскировки REALITY
(см. диагностику tcpdump в [05](05-operations.md)). CDN ([07](07-cdn.md)) обходит это через чужие
адреса, но зависит от того, пропускает ли сеть сам CDN.

Этот вход убирает TLS совсем. Соединение шифрует сам VLESS (**VLESS Encryption**, Xray v25.9+):

```
Клиент ──TCP/ENC_PORT── [рукопожатие VLESS Encryption: ML-KEM-768 + X25519] ── Xray (вход vless-enc) → интернет
                         (ENC_MODE=random: все байты, включая рукопожатие, выглядят случайными)
```

* **Нет ClientHello, SNI, сертификатов** — нечему «не понравиться» на рукопожатии TLS.
* **Шифрование** — AES-GCM / ChaCha20-Poly1305 с ключом сессии из постквантового обмена
  ML-KEM-768 + X25519; **сервер аутентифицируется** ключом X25519 (клиент знает его из ссылки),
  подменить сервер нельзя. Без ключа из ссылки подключиться к серверу нельзя.
* **XTLS Vision** сверху выравнивает размеры пакетов вложенного TLS (сайты внутри туннеля), чтобы
  не было характерной картины «TLS внутри TLS».
* Повторные подключения — **0-RTT** (билет действует 600 с), без лишней задержки.

## Режимы (`ENC_MODE`)

| Режим | Как выглядит трафик |
|---|---|
| `random` (по умолчанию) | весь поток, включая рукопожатие, неотличим от случайных байтов |
| `xorpub` | открытые ключи в рукопожатии замаскированы; записи с заголовками как у TLS |
| `native` | записи с заголовками данных TLS (`17 03 03 …`), но без рукопожатия TLS |

Смена режима не требует новых ключей, но меняет ссылку — раздайте пользователям новые.

## Риски — честно

* **Нет маскировки под сайт.** REALITY для постороннего выглядит как настоящий сайт; этот порт —
  нет: на произвольные данные он просто закрывает соединение. Активная проверка увидит «неизвестный
  сервис на нестандартном порту».
* **«Полностью случайный» трафик** в ряде стран (Китай, Иран) научились выделять и блокировать.
  Как поведёт себя ваш провайдер — можно узнать только проверкой. Если `random` режется,
  попробуйте `native`.
* **Белые списки протоколов.** Если в сети (часто — мобильной, в отдельных регионах) разрешены только
  известные протоколы, неопознанный поток не пройдёт ни в каком режиме.
* **Клиенты** — только на ядре **Xray** свежих версий: v2rayNG, v2rayN, v2RayTun. Hiddify, NekoBox,
  Karing и другие на sing-box VLESS Encryption не поддерживают.

## Включение

`config.env`:
```
ENC_ENABLE="yes"
ENC_PORT="47443"      # любой свободный TCP-порт
ENC_MODE="random"
```
```bash
cd /opt/vpn-https-debian && git pull
sudo ./scripts/02-firewall.sh                    # откроет TCP/ENC_PORT (подтвердите SSH в течение 60 с)
sudo ./scripts/03-install-vpn.sh                 # ключи (xray vlessenc) и вход vless-enc
sudo ./scripts/vpn-user.sh selftest ivan enc     # проверка с сервера
sudo ./scripts/vpn-user.sh link ivan             # третья ссылка — «VLESS Encryption без TLS»
```

Если у хостера есть свой firewall в панели — откройте там тот же TCP-порт.

Ссылка выглядит так:
```
vless://<uuid>@<IP>:47443?encryption=mlkem768x25519plus.random.0rtt.<ключ>&security=none&type=tcp&flow=xtls-rprx-vision#ivan@IP (ENC)
```
Импорт — как обычно. В приложении проверьте, что в профиле **Encryption** = длинная строка
`mlkem768x25519plus…` (не `none`), **Security** = `none`, **Flow** = `xtls-rprx-vision`.
Фрагментацию (Fragment) в приложении держите выключенной — здесь нет ClientHello, дробить нечего.

## Проверка и диагностика

```bash
sudo ./scripts/healthcheck.sh                    # раздел «VLESS Encryption»
sudo ./scripts/vpn-user.sh selftest ivan enc
journalctl -u xray -n 50 --no-pager              # ошибки входа vless-enc
```

| Симптом | Причина |
|---|---|
| `selftest … enc` не проходит | сервер: `03-install-vpn.sh` не запускался после включения, или в журнале Xray ошибка конфигурации |
| `selftest` проходит, телефон — таймаут на подключении | порт закрыт: `02-firewall.sh` не запускался, или firewall в панели хостера |
| подключение есть, но обрывается через несколько секунд/килобайт | провайдер режет «неизвестный» поток — попробуйте `ENC_MODE="native"` (новые ссылки), другой порт или другую сеть |
| в приложении ошибка про `encryption` / профиль не импортируется | клиент не поддерживает VLESS Encryption — обновите или используйте v2rayNG |
