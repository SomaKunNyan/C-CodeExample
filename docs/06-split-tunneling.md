# 06. Домены мимо туннеля (split exclude)

По умолчанию **весь** трафик клиента идёт через VPN (`route = default`). Белый список позволяет
пустить трафик к выбранным доменам и сетям напрямую, через обычный интернет клиента.

## Как это работает

Протокол OpenConnect исключает из туннеля **сети (IP/CIDR), а не домены**. Поэтому:

1. Вы перечисляете домены и сети в файле `split-exclude.txt`.
2. `scripts/update-split-routes.sh` разрешает домены в IP через **тот же unbound, которым пользуются
   VPN-клиенты** (поэтому адреса совпадают), расширяет адреса до подсети (`/24` для IPv4, `/48` для
   IPv6 — CDN меняют IP внутри подсети), склеивает соседние подсети и записывает строки
   `no-route = ...` в блок между маркерами в `/etc/ocserv/ocserv.conf`.
3. Конфиг проверяется `ocserv -t` и применяется через `systemctl reload ocserv` — **активные
   сессии не рвутся**. Новый список клиенты получают при следующем подключении.
4. Таймер `vpn-split-routes.timer` повторяет это ежедневно. Адреса, увиденные за последние
   `SPLIT_KEEP_DAYS` дней, сохраняются (`/var/lib/vpn-https-debian/split-exclude-state.json`):
   если домен временно не разрешился или CDN сменил адрес, исключение не пропадёт.

Клиент получает список при подключении и сам прописывает маршруты — на устройствах ничего
настраивать не нужно.

## Настройка

```bash
cd /opt/vpn-https-debian
cp split-exclude.example.txt split-exclude.txt
nano split-exclude.txt
sudo ./scripts/update-split-routes.sh
```

Формат файла — одна запись на строку, `#` — комментарий:
```
bank.example.ru          # домен
www.bank.example.ru      # поддомены — отдельными строками
госуслуги.рф             # кириллические домены — как есть
203.0.113.0/24           # сеть целиком (если известны диапазоны сервиса)
```

* Маски `*.example.com` не поддерживаются: через DNS нельзя узнать все поддомены.
  Откройте сайт с включённым VPN и посмотрите в инструментах разработчика браузера (вкладка
  Network), к каким доменам он обращается — их и добавьте.
* Частные адреса (`10/8`, `192.168/16`...), пул VPN и IP самого сервера в исключения не попадают.
* Если IPv6 в туннеле выключен (`VPN_NET6` пуст), исключаются только IPv4-адреса.

Команды:
```bash
sudo ./scripts/update-split-routes.sh          # обновить сейчас
sudo ./scripts/update-split-routes.sh --show   # текущие исключения
systemctl list-timers vpn-split-routes.timer   # когда следующее обновление
journalctl -u vpn-split-routes                 # журнал обновлений
```
Чтобы отключить исключения — очистите или удалите `split-exclude.txt` и запустите скрипт.

## Параметры (`config.env`)

| Параметр | По умолчанию | Значение |
|---|---|---|
| `SPLIT_EXCLUDE_FILE` | `/opt/vpn-https-debian/split-exclude.txt` | файл со списком |
| `SPLIT_V4_PREFIX` | `24` | до какой подсети расширять IPv4-адрес (меньше число — шире подсеть, меньше маршрутов) |
| `SPLIT_V6_PREFIX` | `48` | то же для IPv6 |
| `SPLIT_KEEP_DAYS` | `7` | сколько дней помнить ранее найденные адреса |
| `SPLIT_MAX_ROUTES` | `200` | лимит маршрутов: при превышении список **не применяется**, остаётся прежний |

## Проверка на клиенте

Подключитесь к VPN заново (маршруты выдаются при подключении), затем:

| ОС | Команда | Ожидается |
|---|---|---|
| Linux | `ip route get <IP домена>` | `dev` — физический интерфейс (`wlan0`, `eth0`), не `tun0` |
| macOS | `route -n get <IP домена>` | `interface: en0`, не `utun*` |
| Windows | `Find-NetRoute -RemoteIPAddress <IP домена>` | интерфейс Wi-Fi/Ethernet, не VPN-адаптер |

Или откройте https://ifconfig.me — без исключения он покажет IP сервера; если добавить в список
`ifconfig.me`, — ваш домашний IP.

## Ограничения

* **CDN:** у сайтов за Cloudflare/Akamai/и т.п. один IP обслуживает тысячи сайтов — они тоже пойдут
  мимо туннеля. Для таких сайтов исключение по домену неточное.
* **Лимит маршрутов:** клиенты (особенно мобильные) принимают ограниченное число маршрутов.
  Исключить «все сети страны» так не получится.
* **DNS остаётся в туннеле** (`tunnel-all-dns`): запросы к исключённым доменам тоже идут через VPN.
  Гео-CDN может выдать адрес, оптимальный для региона сервера, — обычно это не мешает.
* **Безопасность:** трафик к исключённым сайтам идёт без VPN: сайт видит реальный IP клиента,
  провайдер клиента — факт обращения (содержимое защищено HTTPS самого сайта).
* **Клиенты:** исключения поддерживают OpenConnect (Linux, Windows, macOS) и Cisco Secure Client.
  На Android у открытого клиента OpenConnect поддержка зависит от версии Android — проверьте
  по таблице выше.
