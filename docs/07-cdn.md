# 07. Запасной вход через CDN (Cloudflare)

## Зачем

Если провайдер режет соединения **к IP вашего сервера** (TCP проходит, но TLS-сессия обрывается на
рукопожатии — см. диагностику в [05](05-operations.md)), никакая маскировка протокола не поможет.
Помогает другое: подключаться **не к серверу, а к CDN**. Адреса CDN обслуживают тысячи обычных
сайтов, и провайдеру видно только соединение с Cloudflare.

```
Телефон ─TLS (SNI = cdn.ваш-домен)─▶ Cloudflare ─HTTPS─▶ ваш сервер :443
                                                          │ REALITY: «чужое» имя → сайт-заглушке
                                                          ▼
                                              nginx 127.0.0.1:8443 (сертификат cdn.ваш-домен)
                                                          │ секретный путь XHTTP
                                                          ▼
                                              Xray 127.0.0.1:10444 (вход vless-cdn) → интернет
```

Отдельный порт не нужен: Cloudflare приходит на тот же 443. REALITY не узнаёт имя CDN-домена и, как
для любого постороннего посетителя, передаёт соединение сайту-заглушке; nginx по имени отдаёт
запросы с секретным путём во второй вход Xray, остальным — обычный сайт.

Прямой REALITY остаётся основным (быстрее); CDN — запасной вариант для сетей, где прямой режется.
У пользователя в приложении два профиля, работает тот, что проходит в его сети.

## Настройка Cloudflare (один раз)

1. Аккаунт на cloudflare.com (тариф Free), «Add a site» → ваш домен.
2. У регистратора домена замените DNS-серверы на выданные Cloudflare (`*.ns.cloudflare.com`).
3. **DNS → Records:**
   * основной домен (`@`, для REALITY и сайта-заглушки) → IP сервера, облако **серое** (DNS only);
   * `cdn` → IP сервера, облако **оранжевое** (Proxied).
4. **SSL/TLS → Overview:** режим **Full (strict)**.
5. **Network:** `HTTP/2` и `HTTP/2 to Origin` можно оставить по умолчанию; `WebSockets` не нужен.
6. На время первого выпуска сертификата: **SSL/TLS → Edge Certificates → Always Use HTTPS — выкл.**
   (Let's Encrypt проверяет домен по HTTP; после выпуска можно включить обратно — продление
   пройдёт и через HTTPS).

### Сертификаты: зачем ещё Let's Encrypt, если у Cloudflare уже есть

Соединение через CDN состоит из двух отдельных TLS-участков, и у каждого свой сертификат:

```
Телефон ──TLS #1──▶ Cloudflare ──TLS #2──▶ ваш сервер (nginx)
          сертификат Cloudflare      сертификат на сервере (Let's Encrypt)
          (Edge Certificate)
```

* **Edge Certificate** Cloudflare выпускает сам — он защищает участок «клиент → Cloudflare».
* Участок «Cloudflare → сервер» при режиме **Full (strict)** требует на сервере действующий
  сертификат на CDN-домен; без него Cloudflare отвечает ошибкой **526**. Его выпускает `self-site.sh`
  (один сертификат Let's Encrypt на `VPN_DOMAIN` и `CDN_DOMAIN`, с автопродлением) — делать
  ничего не нужно.
* Основному домену (`VPN_DOMAIN`, серое облако) Let's Encrypt нужен в любом случае: к нему
  подключаются напрямую, мимо Cloudflare, и REALITY показывает посетителям и сканерам именно этот
  сертификат.

Не используйте вместо этого:
* **Cloudflare Origin Certificate** — ему доверяет только Cloudflare; для `VPN_DOMAIN` браузеры и
  сканеры увидят недоверенный сертификат, и маскировка под обычный сайт пропадёт;
* режимы **Flexible** / **Full** без strict — Flexible ходит на сервер по HTTP (порт 80 отвечает
  редиректом — получится петля), Full не проверяет сертификат сервера.

## Настройка сервера

`config.env`:
```
REALITY_SELF_SITE="yes"
VPN_DOMAIN="softiai.shop"
ACME_EMAIL="you@example.com"
CDN_ENABLE="yes"
CDN_DOMAIN="cdn.softiai.shop"
```
```bash
sudo ./scripts/03-install-vpn.sh                 # сертификат на оба имени, vhost CDN, вход Xray
sudo ./scripts/vpn-user.sh selftest ivan cdn     # проверка всей цепочки через Cloudflare
sudo ./scripts/vpn-user.sh link ivan             # две ссылки: REALITY и CDN
```

Скрипт проверяет, что `CDN_DOMAIN` указывает на Cloudflare (а не прямо на сервер — это означало бы
серое облако), выпускает один сертификат Let's Encrypt на основной и CDN-домен и после выпуска
проверяет, что виртуальный хост CDN отвечает.

## Клиенты

Ссылка CDN: `security=tls`, `sni`/`host` = CDN-домен, `type=xhttp`, `mode=packet-up` (CDN пересылает
отдельные HTTP-запросы и плохо переносит длинные потоковые загрузки). Нужен клиент на ядре Xray
(v2rayNG, v2rayN, v2RayTun, V2Box…). Импорт — как обычно, из буфера или QR.

## Ограничения — честно

* **Скорость и задержка** ниже, чем у прямого REALITY: лишний узел и режим `packet-up`.
* **Доступность Cloudflare из РФ** меняется: по сообщениям, в части сетей его замедляют. Проверяйте
  из своей сети; если Cloudflare режется — тот же подход работает с другим CDN, поддерживающим
  проксирование HTTP/2 к вашему серверу (настройка на стороне CDN другая, серверная часть та же).
* **Условия Cloudflare.** Бесплатный тариф рассчитан на сайты; VPN-трафик через него — серая зона
  условий использования. Для нескольких пользователей обычно незаметно, при больших объёмах аккаунт
  могут ограничить.
* **IP клиентов** в `vpn-user.sh list` для CDN-подключений — `127.0.0.1` (соединение приходит через
  Cloudflare и nginx).
* Не используйте «подмену домена» (чужое имя в SNI, свой — в Host): это нарушает правила CDN и может
  перестать работать в любой момент. Здесь SNI = ваш собственный CDN-домен.

## Проверка и диагностика

```bash
sudo ./scripts/healthcheck.sh                    # раздел «CDN»
curl -sI https://cdn.softiai.shop/               # 200, заголовок server: cloudflare
sudo ./scripts/vpn-user.sh selftest ivan cdn
```

| Симптом | Причина |
|---|---|
| `selftest ... cdn` не проходит, `curl https://cdn.…/` даёт 526 | у Cloudflare Full (strict), а сертификат на сервере не содержит CDN-домен — перезапустите `03-install-vpn.sh` |
| 521 / 522 | Cloudflare не может подключиться к серверу на 443: firewall хостера, сервер выключен |
| `curl` работает, клиент — нет | старый профиль в приложении; в профиле должен быть `tls`, а не `reality`, и `packet-up` |
| Через CDN медленно | ожидаемо; для скорости используйте прямой профиль там, где он работает |
